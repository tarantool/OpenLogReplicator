# PRD — Product Requirements Documents

PRD описывают **зачем** существует фича, **какую проблему** пользователя она решает и **как** пользователь проходит сценарий. Документ лёгкий: цель — сохранить мотивацию и пользовательский путь, а не выписать полную спецификацию API.

## Назначение

- Зафиксировать продуктовый замысел так, чтобы через месяцы было ясно, ради чего написаны конкретные компоненты и тесты.
- Связать продуктовый язык с техническими артефактами (ADR, BDD-сценарии, код).
- Дать общую точку опоры разработчикам, тестировщикам, аналитикам и AI-агентам.

## Когда писать PRD

PRD нужен для:

- Существенного расширения существующей функции, затрагивающего несколько модулей.
- Существенного изменения пользовательского сценария (новый путь, новая роль, новый режим).
- Решения, где «почему именно так» не очевидно из кода и тестов.

## Формат файла

Имя файла: `kebab-case-slug.md`. Для фич, привязанных к тикету Jira, допустим префикс `JIRA-123-slug.md`.

Шаблон:

```markdown
# <Название фичи>

## Статус

Один из: `Черновик` · `Согласован` · `В реализации` · `Готово` · `Отменён`

## Проблема

Что болит у пользователя сегодня. Какой контекст и какие сценарии приводят к боли. Без техдолга и архитектуры — только пользователь.

## Ценность

Что меняется после поставки. Как измеряем успех (метрики, qualitative-сигналы).

## Пользовательский путь

Пошагово: что делает пользователь, что видит на каждом шаге, какие ответвления/ошибки. Внешне похоже на BDD, но без привязки к шагам теста.

## Границы

- Что входит в скоуп.
- Что явно вне скоупа (и почему).

## Открытые вопросы

Что нужно уточнить до/во время реализации.

## Ссылки

- Связанные ADR из `../adr/`
- Связанные BDD-сценарии из `../bdd/`
- Внешние ссылки: тикеты, дизайн-доки, аналитика
```

## Чего в PRD не должно быть

- Конкретных имён классов/модулей/файлов — это территория ADR.
- Пошаговых тестовых сценариев в формате Given/When/Then — это территория BDD.

## Связи с другими разделами

- PRD ссылается на `../adr/`, описывающие архитектурные ограничения фичи.
- BDD-сценарии в `../bdd/` трассируются до PRD, чьё поведение они описывают.
